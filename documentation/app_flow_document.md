# Invoice Otomatis SaaS App Flow

## Onboarding and Sign-In/Sign-Up
When a new user arrives, they land on a simple page that explains what the app does and prompts them to create an account or sign in. The user can choose to sign up with their email and a password, or they can request a magic link that arrives in their inbox for passwordless login. Clerk handles email verification and shows clear messages if the email is not valid or the link expires. If the user forgets their password, they click "Forgot Password," enter their email, and receive a reset link. Once they set a new password or use the magic link, they end up on the main dashboard. They can sign out at any time by clicking the avatar icon in the header and selecting "Sign Out."

## Main Dashboard or Home Page
After signing in, the user sees the dashboard with a top header, a sidebar on the left, and content on the right. The header shows the user’s name and a settings icon. The sidebar lists links to Dashboard, Clients, Invoices, Reports, Billing, and Settings. In the main area, summary cards display total invoices this month, outstanding balances, and upcoming due dates. A button at the top invites the user to create a new invoice or add a new client. From here, the user can click any menu item in the sidebar to move to another page.

## Detailed Feature Flows and Page Transitions
When the user clicks Clients in the sidebar, they arrive at the Clients page. The page shows a table of existing clients with their names, contact details, and actions. To add a new client, the user clicks "New Client," and a form appears in a dialog. The form fields include name, email, address, and phone number. The user fills in the fields and clicks "Save." The system validates the data with Zod and React Hook Form. If validation fails, errors appear below each field. When the save succeeds, the dialog closes and the new client shows in the table.

On the Invoices page, the user sees a list of invoices with status labels such as Draft, Sent, Paid, or Overdue. Clicking "New Invoice" opens a form in a new page. The form asks the user to select a client from a dropdown, set an invoice date and due date, and add line items with descriptions, quantities, and prices. As they add each item, the total updates automatically. Once the user submits, the invoice is saved in Supabase and they are redirected to the invoice detail page. On that detail page, the invoice renders in a template component and offers buttons to "Send via Email," "Download PDF," or "Mark as Paid." Sending via email triggers a server action that calls an external email service. Downloading PDF uses a print-friendly layout. Marking as paid updates the status in the database and the user returns to the invoice list.

If a user has the free plan and tries to create more than the allowed number of invoices, the app shows a prompt that says they need to upgrade to access more invoices. Clicking the prompt leads to the Billing page.

## Settings and Account Management
In the Settings page, the user finds two tabs: Account and Billing. Under Account, they can update their profile details like name, email, and password, or connect social logins if supported. Changing the email triggers a verification email. Under Billing, they see their current plan, next billing date, and payment method. A button labeled "Change Plan" takes them to a page where they can choose between the Rp 50k and Rp 150k plans. Selecting a plan starts a Stripe checkout session in a server action. After successful payment, a Stripe webhook updates the user’s subscription status in Supabase. The Billing page then reflects the new status and recurring billing date. From Settings, a link returns the user to the Dashboard.

## Error States and Alternate Paths
If the user loses internet connection, the UI shows a banner telling them they are offline. Forms are disabled until connectivity returns. When a form submission fails due to validation or server errors, an error message appears at the top of the form and specific fields highlight the problem. If a Stripe checkout fails, the user sees an error page with the failure reason and a link to retry. Unauthorized access to a page redirects the user back to the login screen or shows an "Access Denied" message if they are already signed in. Invoices that fail to send by email show a retry button. Automated reminder functions log errors when they cannot contact the messaging service, and the system retries on the next scheduled run.

## Conclusion and Overall App Journey
A typical user journey begins with signing up and choosing a subscription plan. After landing on the dashboard, the user adds clients and generates invoices in a few simple steps. They can download or email invoices, track payment status, and receive automated reminders when invoices approach or pass their due date. Reporting pages give insights into revenue and overdue balances. At any point, users can update their profile, change plans, or sign out. Behind the scenes, Clerk secures authentication, Supabase stores all data with strict access control, Stripe handles subscriptions, and scheduled functions send reminders. The result is a seamless experience from sign-up to daily invoicing tasks for freelancers and UMKM users.
